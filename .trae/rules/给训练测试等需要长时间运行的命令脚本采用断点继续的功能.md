# 长时间运行脚本必须采用断点继续功能

适用于：训练、配比扫描、批量评估、数据采集、注入协议、闭环重验等一切可能超过几分钟的 GPU/CPU 命令脚本。

## 强制范围（2026-11-23 起收紧）

**今后新写的所有长跑脚本（含评估类）一律自带断点续跑，无豁免。**
"短任务不做续跑改造"的旧豁免取消——教训：判据⑥评估跑 20 分钟遇关机全损重跑；
run_eval 已补 trial 级续跑（见先例）。写新脚本时，断点续跑不是可选项，是验收项。

## 硬性要求（三条缺一不可）

1. **逐结果落盘**：每完成一个最小工作单元（组/episode/样本/测试/trial），立即把结果追加写入 JSONL 日志并 flush，不攒批、不内存缓存到最后一次性写。
2. **固定种子**：随机种子与工作单元索引绑定（如 `seed = base_seed + crc32(unit_id) % 100000`，注意用 crc32 等稳定哈希——Python 内置 `hash()` 受 PYTHONHASHSEED 随机化，跨进程不可复现），保证断点恢复后同一单元可复现、已跑过的单元不会因重启而改变。
3. **启动查盘跳过**：脚本启动时先查已有 checkpoint / 日志，跳过已完成的工作单元，从断点继续——不允许"重跑覆盖"或"从头再来"。

## 推荐实现模式（参照 `rl/train_rl.py`）

```python
# 启动时：查盘跳过
if ckpt_path.exists():
    ck = torch.load(ckpt_path, map_location=device)
    model.load_state_dict(ck["model"])
    opt.load_state_dict(ck["opt"])
    start_step = ck["step"] + 1
    monitor_history = ck.get("monitor_history", [])

# 循环内：每 N 步保存完整状态（模型 + 优化器 + 步数 + 监控历史）
if (step + 1) % save_every == 0 or step == total - 1:
    torch.save({"step": step, "model": model.state_dict(),
                "opt": opt.state_dict(), "monitor_history": monitor_history,
                "args": vars(args)}, ckpt_path)
```

- checkpoint 保存**完整可恢复状态**：模型权重 + 优化器状态 + 进度计数器 + 随机种子参数（`vars(args)`），不能只存权重
- 最终产物（如 `*_final.pt`）与断点 checkpoint 分开命名
- 日志文件以 append 模式打开，断点恢复后追加续写

## 已有先例

- `rl/train_rl.py`：按组断点（checkpoint 存完整状态），查盘跳过已验证（冒烟"从第 10 组继续、0 组重跑"）
- `eval/run_eval.py`：trial 级断点（`Progress` 类：JSONL 逐 trial 落盘 + `torch.manual_seed(base+crc32(unit))` 单元级种子 + 启动查盘跳过）——评估类脚本续跑的首个实现（2026-11-23，判据⑥关机全损事件直接催生）
- `eval/inject_events.py`：单元级 JSONL + crc32 种子 + 查盘跳过，断点续跑在真实崩溃中验证有效
- `memory/buffer.py`：JSONL append+flush + 启动查盘载入（非训练资产的续跑同逻辑）
